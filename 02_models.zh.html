本页的比喻 — 餐厅厨房

推理很像接单出菜的厨房工作：读取订单（预填充）、一盘一盘出菜（解码）、预先备好料的食材盒（KV缓存）、安排专业厨师（MoE）。每个层级还标注了比喻在哪里不再贴切。资料来源：《Inference Engineering》2.1–2.2节[1]。

为什么要了解模型内部

原因 1

又快又便宜，质量不变

该书将推理工程定义为“在不牺牲质量的前提下”，让模型既快速、又便宜、又可靠。要知道哪些地方可以减少，必须先了解模型内部在做什么[1]。

原因 2

时间花在两个地方

推理的大部分时间和资源，都花在预填充阶段生成KV缓存，以及解码阶段生成logit上。两者都需要运行庞大的神经网络[1]。

原因 3

架构决定引擎支持

只要架构相同，即使规模、变体或微调不同，也可以直接使用已经优化好的部署方案。因此我们先从读懂config.json中的一行名称开始[1]。

博士

博士的一句话：想要提速，先得知道时间从哪里漏掉。

大图景 — 从订单到下一个词元

基于Transformer的生成模型分为两类。自回归词元生成根据词元序列预测下一个词元（LLM）；迭代去噪则从随机噪声出发，通过扩散逐步细化结果（图像生成）[1]。本页讲的是前者，即LLM。图像生成将在书中2.3节继续讲解。

0 分词（应用聊天模板）1 预填充 → KV缓存2 解码：一次前向传播 = 一个词元3 logit → 概率 → 抽取4 停止词元 · 上下文窗口 · max_tokens

编码器与解码器

编码器把输入转换为包含语义的内部表示，解码器再利用这一表示生成输出。现在的LLM大多是纯解码器，纯编码器则较少见，如BERT系列嵌入模型。语音转写模型Whisper属于编码器-解码器结构[1]。

简史

1950年代硬件感知机 → 反向传播训练多层感知机 → 2000年代深度神经网络 → 2012年AlexNet展示GPU的威力 → 2017年《Attention Is All You Need》提出Transformer[1][2]。

1基础

线性层与矩阵乘法 — 神经网络的基本运作

模型：y = xW + b日常：酱汁配方表

用日常来比喻

用配料的量（输入）乘以配方的比例（权重）后相加，再加上基础调味（偏置），就得到酱汁的味道分数（输出）。即使经过两张配方表，也可以先把两张表相乘，合并成一张表，得到相同的结果。

在神经网络中

节点是一个小程序，它把输入乘以权重、再加上偏置后输出；节点聚集起来就形成层。线性层把输入向量乘以权重矩阵，再加上偏置向量。两个线性层相当于把矩阵相乘后合并成的一层[1]。

解析 — 为什么会合并

  1. 第1层：y = xW₁ + b₁。第2层：z = yW₂ + b₂。
  2. 把第1层代入第2层得到 z = x(W₁W₂) + (b₁W₂ + b₂)。
  3. 令 W₃ = W₁W₂，b₃ = b₁W₂ + b₂，则 z = xW₃ + b₃。两层被折叠成了一层。这就是上面实验中两个网格分毫不差的原因。
  4. LLM的大部分权重都在这类线性层中，矩阵的数值在训练时确定[1]。

本层级的局限：只堆叠线性层，无论多深都等同于一层，堆叠也就失去了意义。→ 下一层级将介绍让它“不被折叠”的机制。

用公式看

若 x ∈ ℝ1×d，W₁ ∈ ℝd×h，W₂ ∈ ℝh×k，则 W₃ = W₁W₂ ∈ ℝd×k。这是因为矩阵乘法满足结合律 (xW₁)W₂ = x(W₁W₂)。书中图2.3正是直接展示了这一计算[1]。

2基础

激活函数 — 让层不被折叠的折线

模型：ReLU(x) = max(0, x)果蝇：放电阈值（辅助比喻）

在果蝇身上

果蝇神经元的输入必须超过阈值才会放电。阈值以下的输入会直接消失。它不是“照单全收、简单相加”地处理接收到的信号，这一点与ReLU相似。

局限：真实神经元发出的是电脉冲（尖峰），不像ReLU那样输出与输入成正比的值。

在神经网络中

激活函数是非线性的，因此能阻止矩阵乘法被折叠成一层；它几乎处处可微，有助于反向传播学习。ReLU在x大于0时返回x，否则返回0。ReLU、SiLU、Swish、SwiGLU既快速又容易训练[1]。

实验 ② — 区分圆盘与环形（隐藏节点8个）

激活

动手看看 — 逐个判定验证盘子

解析 — 许多折线汇聚成曲线

  1. 没有激活函数时，即使有隐藏层，整个模型也等同于一个线性层，决策边界就是一条直线。圆盘和环形无法用一条直线分开。
  2. ReLU把负数折为0。多个被折叠的面叠加起来，就能模拟圆形的边界。
  3. SiLU等把负数区域平滑地拉向0附近的函数，也做着同样的事。书中指出，大多数激活函数都遵循“负数趋近0，正数保持不变”的同一思路[1]。
  4. 分数由未参与训练的验证点计算得出。

本层级的局限：神经网络只接收数字向量，也只输出数字向量。它既不能直接接收文字，也不能用文字回答。→ 下一层级：词元。

用公式看

隐藏层 h = φ(xW₁ + b₁)，输出 p = σ(hW₂ + b₂)。若φ为恒等函数，则 p = σ(x(W₁W₂) + …)，决策边界 xW₃ + b₃ = 0 为一条直线。ReLU(z) = max(0, z)，SiLU(z) = z·σ(z)。训练：交叉熵，全批次梯度下降，学习率0.8，种子3（权重）·5（训练）·77（验证）。

果蝇研究员

别看训练分数，先看空心点（验证）的分数。那才是真实的。

3进阶

词元与选择下一个词元

模型：logit → 概率 → 抽取日常：把订单写成菜单编号

在厨房里

客人的话不会原样传给厨房，而是转成菜单编号再送进去。编号转换不是由厨师完成，而是由一张表完成。常点的菜用一个编号，少见的订单则用多个编号组合来记录。

局限：菜单编号由人来定，而分词器的词表是从数据中生成的，且每个模型都不同。

在神经网络中

词元是代表文本片段的数字。现在的LLM使用子词分词，因此一个词元可能是一个完整单词，也可能只是单词的一部分。分词器是不借助神经网络、只把字符串与数字一一对应的表；模型的输出层则会生成一个与词表大小一样长的logit向量[1]。

书中的示例：6个单词、41个字符，共8个词元

词元编号与书中图2.5完全一致[1]。不常见的单词“Inference”被拆成了两个词元。词元越少，同样的输出就能越快完成。

解析 — 一个词元产生的五个步骤

  1. 把输入（提示、对话、工具说明）套上聊天模板，拼成一行后进行分词。这就是推理的第0步。
  2. 模型会对词表中的每个词元计算一个logit。
  3. 对logit进行归一化即得到概率。温度在归一化之前直接调整logit本身。
  4. top-k只保留概率最高的k个；top-p则保留累计概率达到p的最小集合，并重新归一化。
  5. 按剩余概率随机抽取一个。温度为0或top-k为1时，总是选择概率最高的词元。遇到停止词元，或达到上下文窗口、max_tokens时结束[1]。

本层级的局限：要选下一个词元，必须参考前面的所有词元。句子越长，就越需要一种机制来决定参考哪些、参考多少。→ 下一层级：注意力。

用公式看

pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)。T → 0时为argmax。top-k：在前k个的集合S中取 pᵢ/ΣSp。top-p：取降序累计和首次达到p以上的集合。在结构化输出（如JSON）中，前向传播之后还会使用logit偏置等工具[1]。

用生成式AI来说

聊天机器人设置里的“temperature”调低时，回答总是差不多；调高时则多样但可能跑偏，原因就在这张柱状图里。推理模型会在答案之前多生成一段思考输出，输入、思考和输出加在一起，必须装进上下文窗口[1]。

比喻的局限：实际词表超过10万个，而8个候选的柱状图只是截取了最前面的部分作为示例。
算盘宝

词元少了，账单也会少。分词器的效率就是你的收益率。

4进阶

注意力与KV缓存 — 如何参考前面的词元

模型：softmax(QKᵀ/√dₖ)V日常：备好料的食材盒

在厨房里

收到订单后，先把所有食材处理好装入食材盒（预填充）。之后每出一盘菜，就取出已处理好的食材盒使用，并为新菜品再增加一个食材盒（解码）。每一盘都不需要从头处理。

局限：食材用掉就会减少，但KV缓存会随着词元数和层数持续增长，并占用GPU显存。

在神经网络中

注意力会用当前词元（Q）与之前各词元的表示（K）进行比对以确定权重，然后按此比例混合之前各词元的值（V）。之前词元的K和V保存在GPU显存中的KV缓存里，不需要重复计算[1]。

解析 — Q、K、V与两个阶段

  1. Q（查询）：当前正在生成或修改的词元的表示。K（键）：之前各词元的表示。V（值）：之前各词元经计算后的值[1]。
  2. LLM在自注意力（Q、K、V来自同一序列）上加上因果掩码，使模型看不到后面的词元。图像和多模态模型还会使用交叉注意力[1]。
  3. 注意力层中，多个头（head）并行运行。每个头可以负责不同的关系，例如主谓一致、指代等[1]。
  4. 注意力需要查看当前词元与之前所有词元的关系，因此相对于句子长度是平方时间。书中解释说，借助KV缓存，实际运行时间接近线性。生成一个词元时，不需要重新计算之前词元的K和V，而是直接从缓存中取出[1]。
  5. KV缓存在预填充阶段生成，在解码阶段被使用和更新，默认保存在GPU显存中。存储与复用是书中5.3节的重要主题[1]。

本层级的局限：权重最多的部分不是注意力，而是前馈（线性）层。每生成一个词元，都要完整经过这些庞大的矩阵。→ 下一层级：只使用一部分的混合专家。

用公式看

Attention(Q, K, V) = softmax(QKᵀ/√dₖ)V（Vaswani 等，2017；本书采用 Dao 等，2022 的记法）[1][2][3]。实验 ④-乙的计算：提示长度为P、输出长度为N时，无缓存 = Σt=1..N(P+t) = NP + N(N+1)/2，有缓存 = P + N。每一步的内积计算（P+t次）两种情况相同，缓存减少的是之前词元K·V的重复计算。

用生成式AI来说

粘贴一篇长文档后，等待第一个字出现的时间变长，这是预填充；之后字陆续流出，则是解码。

比喻的局限：实际服务的等待时间还会受排队、网络等其他因素影响。

应用到现场

KV缓存占用的GPU显存 = 同时请求数 × 上下文长度。做服务设计时，除了“权重显存”，还需要单独预留“缓存显存”预算。

比喻的局限：实际大小取决于层数、KV头数和精度，本页只数了层级数量。
博士

博士的一句话：处理过的食材不再重复处理，这就是KV缓存。

5深入

混合专家（MoE）— 用一组小专家替代庞大的矩阵

模型：路由器从128名中选出8名日常：主厨分配专业厨师

读懂名称 — Qwen3MoeForCausalLM

Qwen模型系列（品牌名）
3系列内的架构主版本
Moe混合专家模型
CausalLM因果语言模型：只看前面的词元来预测下一个

完全是书中的解释[1]。因果语言模型与用左右上下文填补空缺的掩码语言模型不同，当今的生成式LLM都是因果语言模型。同一架构中也存在多种规模（例如Llama 8B、70B）、base与instruct变体，以及LoRA等微调，但架构本身不会改变。

在厨房里

不是让一名厨师做所有菜，而是设立128名专业厨师，由主厨（路由器）每盘只叫8名。只有一位客人时，只有8名在忙。但晚餐高峰时客人一多，每盘都会叫不同的厨师，结果几乎所有人都忙起来了。

局限：实际路由器不是每盘只选一次，而是在94层的每一层都重新选择。此外，休息的专家也必须保留在显存中。

在神经网络中

MoE为线性层增加了稀疏性。不设一个大矩阵，而是设数百个小矩阵（专家），每次输入只激活其中几个。Qwen3-235B-A22B每次请求在2350亿参数中激活220亿参数，并在94个层中每层从128个专家中选出8个。在批量推理中，每个请求激活的专家各不相同，因此几乎所有参数都应视为处于激活状态[1]。

实验 ⑤ — 一层、128个专家，改变批次大小

1

动手看看 — 主厨把词元派给专家

解析 — 单独使用与在服务器上使用

  1. 神经网络的密度由层之间的连接数决定。连接越密集，能容纳的信息越多；越稀疏，计算和显存占用就越少[1]。
  2. 单独运行一个请求时，激活参数很少，因此MoE非常高效（本地单请求）。
  3. 增大批次时，每个词元选择的专家各不相同，被激活专家的并集会迅速扩大。在上面的实验中，批次为64时几乎所有专家都会被激活。
  4. 因此在大规模服务中，会通过专家并行把专家分配到多块GPU上，从而发挥稀疏性的优势。书中图2.9的示例是8块GPU各负责16个专家，路由器则在每块GPU上复制一份[1]。
  5. 32B以下，尤其是8B以下的模型，传统的稠密结构通常更高效；而像Tab自动补全这样的窄领域模型，整个模型实际上就是一个专家，MoE的收益很小[1]。

本层级的局限：仅凭激活参数数量无法计算服务器成本，还必须同时考虑批次、并行方式和显存。这部分计算（算术强度、瓶颈）将在书中2.4节和5.4.2节继续讲解。

用公式看

设有E个专家，每个词元选K个，假设路由均匀分布，则在批次B中某个专家从未被选中的概率为 (1 − K/E)B，激活比例的期望值为 1 − (1 − K/E)B。当E = 128，K = 8，B = 64时，1 − (15/16)64 ≈ 0.984。上面的实验使用了存在热门专家的偏斜路由（种子2026），因此结果略低于此值。两者都是示意模型。

应用到现场

不要看到“激活22B”的标签就只准备22B的GPU显存。所有专家都必须加载到显存中，而且增大批次后，每一步几乎都会读取全部专家的权重。

比喻的局限：实际路由分布因模型和数据而异，本页的偏斜程度是一种假设。

对决 — 在服务器上，MoE真的只需要十六分之一的工作量吗？

条件：Qwen3式MoE层（128个专家，每个词元8个），服务器解码的一步中有64个词元同时进入（批次64）。在94个层中测量“本步激活的专家比例”，并与各自的预测进行比较。判定标准是预测误差（越小越好）。

总结 — 五个层级一览

层级概念新获得的能力局限（为何需要下一层级）厨房比喻
①线性层·矩阵乘法把向量变换为另一个向量即使堆叠，也会折叠成一层酱汁配方表
②激活函数堆叠层以形成曲线边界只处理数字，不认识文字（辅助）果蝇放电阈值
③词元·logit·采样文字 ↔ 数字，以概率选择下一个词元必须参考前面的所有词元把订单转为菜单编号
④注意力·KV缓存与前面词元的关系，无需重算即可接着生成每次都要完整经过占大部分权重的线性层预先备好料的食材盒
⑤混合专家每个词元只使用部分专家批量时几乎全部激活，仍需全部显存主厨分配厨师

术语对照卡

隐藏状态

隐藏层输出、供下一层读取的结果。文本中维度会扩展到数百至数千，图像中则把数百万像素压缩下来[1]。

嵌入层 · LM头

把词元转换为嵌入的输入层，以及把隐藏状态转换为词表大小logit的输出层[1]。

前馈 · 注意力

前馈（MLP）占可学习权重的大部分，注意力次之。归一化和激活函数在规模上只相当于舍入误差水平[1]。

config.json

Hugging Face上所有LLM都有的几十行文件。其中记录了架构名称以及层和向量的大小[1]。

比喻不贴切的地方

  • 配方表的比喻只像矩阵的“相乘再相加”。实际矩阵是数千 × 数千的大小，数值由训练决定。
  • 果蝇的放电阈值只像“进行折叠”这一点。神经网络并不是模仿果蝇的大脑，只是借用了框架。
  • 注意力只是从人类的注意力集中借用了名称。实际上是内积和softmax的计算。
  • 厨房比喻中的“厨师人工成本”与MoE的计算量相似，但不同之处在于：休息的专家同样要占用GPU显存。
