なぜモデルの中を知る必要があるのか

理由 1

速く、安く、品質はそのまま

本は推論エンジニアリングを「品質を犠牲にせず」モデルを速く、安く、信頼できるものにする仕事と定義しています。何を削ってよいかを知るには、モデルの中で何が働いているかを知る必要があります[1]。

理由 2

時間は二か所で使われる

推論の時間と資源の大部分は、プリフィルでKVキャッシュを作る処理と、デコードでロジットを作る処理に使われます。どちらも大きなニューラルネットワークを動かすからです[1]。

理由 3

アーキテクチャがエンジンの対応を決める

同じアーキテクチャであれば、サイズ・派生版・ファインチューニングが違っても、よく最適化された配備をそのまま使えます。そのため、まずconfig.jsonの名前の一行を読む方法から学びます[1]。

1基礎

線形層と行列積 — ニューラルネットワークの基本動作

モデル: y = xW + b日常: ソースの配合表

日常に置き換えると

材料の量（入力）に配合表の比率（重み）を掛けて足し、基本の味付け（バイアス）を加えると、ソースの味の点数（出力）が出てきます。配合表を二回通しても、二つの表をあらかじめ掛け合わせた表一枚で同じ結果が出せます。

ニューラルネットワークでは

ノードは入力に重みを掛けてバイアスを足して返す小さなプログラムで、ノードが集まると層になります。線形層は入力ベクトルに重み行列を掛け、バイアスベクトルを足します。二つの線形層は、行列を掛け合わせてまとめた一つの層と同じです[1]。

実験 ① — 二層を通した格子 vs まとめた一層を通した格子

描画
二層の間

動きで見る — 一つの点が二つの経路を進む

解説 — なぜまとまるのか

  1. 層1: y = xW₁ + b₁。層2: z = yW₂ + b₂。
  2. 層1を層2に入れると z = x(W₁W₂) + (b₁W₂ + b₂)。
  3. W₃ = W₁W₂、b₃ = b₁W₂ + b₂ とおくと z = xW₃ + b₃。二つの層が一つにたたまれました。上の実験で二つの格子が少しもずれない理由です。
  4. LLMの重みの大部分はこのような線形層にあり、行列の値は学習のときに決まります[1]。

この段の限界: 線形層だけを積み重ねても、どれほど深くても一つの層と同じです。層を積む意味がなくなります。→ 次の段で「たたまれないように」する仕組みが出てきます。

数式で見る

x ∈ ℝ1×d、W₁ ∈ ℝd×h、W₂ ∈ ℝh×k のとき W₃ = W₁W₂ ∈ ℝd×k。行列積の結合法則 (xW₁)W₂ = x(W₁W₂) によるものです。本の図2.3はこの計算をそのまま示しています[1]。

2基礎

活性化関数 — 層がたたまれないように折り曲げる

モデル: ReLU(x) = max(0, x)ショウジョウバエ: 発火の閾値（補助のたとえ）

ショウジョウバエでは

ショウジョウバエのニューロンは、入力が閾値を超えないと発火しません。閾値以下の入力はそのまま消えます。受け取った信号を「そのまま足すだけ」にしない点が、ReLUと似ています。

限界: 実際のニューロンは電気信号（スパイク）を出し、ReLUのように入力に正比例する値は出しません。

ニューラルネットワークでは

活性化関数は非線形なので、行列積が一つの層にたたまれるのを防ぎ、（ほぼ）微分可能なので誤差逆伝播による学習を助けます。ReLUはxが0より大きければxを、そうでなければ0を返します。ReLU、SiLU、Swish、SwiGLUは速くて学習しやすい関数です[1]。

実験 ② — 円盤とリングを分ける（隠れノード8個）

活性化

動きで見る — 検証の皿を一つずつ判定

解説 — 折れ線が集まると曲線になる

  1. 活性化がないと、隠れ層があってもモデル全体は一つの線形層と同じで、境界は一本の直線になります。円盤とリングは直線では分けられません。
  2. ReLUは負の数を0に折り曲げます。折れた面が何枚も重なると、丸い境界をまねできます。
  3. SiLUのように負の側を0付近へなめらかに送る関数も同じ働きをします。本では、ほとんどの活性化関数が「負の数は0付近へ、正の数はそのまま」という同じ枠組みに従うと説明されています[1]。
  4. スコアは、訓練に使わなかった検証の点で採点します。

この段の限界: ニューラルネットワークは数字のベクトルを受け取り、数字のベクトルを出すだけです。文字を直接受け取ることも、文字で答えることもできません。→ 次の段: トークン。

数式で見る

隠れ層 h = φ(xW₁ + b₁)、出力 p = σ(hW₂ + b₂)。φ が恒等関数なら p = σ(x(W₁W₂) + …) となり、境界 xW₃ + b₃ = 0 は直線です。ReLU(z) = max(0, z)、SiLU(z) = z·σ(z)。学習: 交差エントロピー、全バッチ勾配降下、学習率 0.8、シード 3（重み）・5（訓練）・77（検証）。

3中級

トークンと次のトークンの選び方

モデル: ロジット → 確率 → 抽出日常: 注文をメニュー番号で書く

厨房では

客の言葉をそのまま厨房に渡さず、メニュー番号に書き換えて送ります。番号の変換は料理人ではなく表一枚が行います。よく出るメニューは番号が一つ、珍しい注文は番号を複数つけて書きます。

限界: メニュー番号は人が決めますが、トークナイザーの語彙はデータから作られ、モデルごとに異なります。

ニューラルネットワークでは

トークンは文字のかけらを表す数字です。最近のLLMはサブワードのトークン化を使い、トークン1つが単語1つのこともあれば単語の一部のこともあります。トークナイザーはニューラルネットワークを使わず、文字列と数字を対応づける表で、モデルの出力層は語彙のサイズと同じ長さのロジットベクトルを出します[1]。

解説 — トークン1つが出てくる五つの手順

  1. 入力（プロンプト・会話・ツールの説明）にチャットテンプレートをかぶせて一列にし、トークン化します。これが推論の0段階です。
  2. モデルは語彙のすべてのトークンについてロジットを出します。
  3. ロジットを正規化すると確率になります。温度は正規化の前に、ロジットそのものを調整します。
  4. top-kは確率の上位k個だけを残し、top-pは確率を足してpになる最小の組だけを残して、再び正規化します。
  5. 残った確率に従ってランダムに一つを抽出します。温度0やtop-k 1なら、いつも最も高いトークンを選びます。停止トークンが出るか、コンテキストウィンドウやmax_tokensに達すると終わります[1]。

この段の限界: 次のトークンを選ぶには、前のすべてのトークンを参照する必要があります。文が長くなるほど、何をどれだけ参照するかを決める仕組みが必要になります。→ 次の段: アテンション。

数式で見る

pᵢ = exp(zᵢ/T) / Σⱼ exp(zⱼ/T)。T → 0 なら argmax。top-k: 上位k個の集合Sで pᵢ/ΣSp。top-p: 降順の累積和が初めてp以上になる集合。構造化出力（JSONなど）では、順伝播の後にロジットバイアスのような道具をさらに使います[1]。

チャットボットの設定で「temperature」を下げると答えがいつも似通い、上げると多様になるが的外れになるのは、この棒グラフのためです。推論モデルは答えの前に思考用の出力列を一つ追加で作り、入力・思考・出力をすべてあわせてコンテキストウィンドウに収める必要があります[1]。

たとえの限界: 実際の語彙は10万を超え、候補8個の棒グラフはその先頭部分だけを切り出した例です。

4中級

アテンションとKVキャッシュ — 前のトークンをどう参照するか

モデル: softmax(QKᵀ/√dₖ)V日常: 下ごしらえしておいた食材トレー

厨房では

注文票を受け取ったら、まず食材をすべて下ごしらえしてトレーに入れておきます（プリフィル）。その後、皿を一つ出すたびに下ごしらえ済みのトレーを取り出して使い、新しい皿の食材トレーを一つ積み増します（デコード）。毎回最初から下ごしらえし直すことはしません。

限界: 食材は使えば減りますが、KVキャッシュはトークンごと・層ごとに増え続け、GPUメモリを占有します。

ニューラルネットワークでは

アテンションは、今のトークン（Q）と前のトークンたちの表現（K）を照らし合わせて重みを決め、前のトークンたちの値（V）をその割合で混ぜ合わせます。前のトークンのK・Vは、GPUメモリのKVキャッシュに保存しておき、二度計算しません[1]。

解説 — Q、K、Vと二つの段階

  1. Q（クエリ）: 今作っている、または直しているトークンの表現。K（キー）: 前のトークンたちの表現。V（バリュー）: 前のトークンたちの計算済みの値[1]。
  2. LLMは自己アテンション（Q・K・Vが同じ列から来る）に因果マスクをかけ、後ろのトークンを見えないようにします。画像・マルチモーダルモデルはクロスアテンションも使います[1]。
  3. アテンション層では複数のヘッドが並列に働きます。ヘッドごとに、主語と動詞の一致、指示語など、異なる関係を担当できます[1]。
  4. アテンションは今のトークンと前のすべてのトークンの関係を見るので、文の長さに対して二乗の時間がかかります。本では、KVキャッシュのおかげで実際には線形に動くと説明されています。トークン1つを作るとき、前のトークンのK・Vを再計算せず、キャッシュから取り出すからです[1]。
  5. KVキャッシュはプリフィルで作られ、デコードで使われて更新され、基本的にはGPUメモリに置かれます。保存と再利用は本の5.3節の大きなテーマです[1]。

この段の限界: 重みが最も多いのはアテンションではなく、フィードフォワード（線形）層です。トークン1つごとに、この巨大な行列全体を通らなければなりません。→ 次の段: 一部だけを使う専門家混合。

数式で見る

Attention(Q, K, V) = softmax(QKᵀ/√dₖ)V（Vaswani ほか 2017；本は Dao ほか 2022 の表記に従う）[1][2][3]。上の実験 ④-イの計算: プロンプトP、出力Nのとき、キャッシュなし = Σt=1..N(P+t) = NP + N(N+1)/2、キャッシュあり = P + N。各段の内積計算（P+t回）は両方とも同じで、キャッシュが減らすのは前のトークンのK・Vの再計算です。

生成AIでいうと

長い文書を貼り付けたとき、最初の文字が出るまでの待ち時間が長くなるのはプリフィル、その後に文字が流れ出てくるのはデコードです。

たとえの限界: 実際のサービスの待ち時間には、行列や通信など別の要因も混ざります。

現場に置き換えると

KVキャッシュは、同時リクエスト数 × コンテキストの長さの分だけGPUメモリを消費します。サービス設計では、「重みのメモリ」とは別に「キャッシュのメモリ」の予算を立てる必要があります。

たとえの限界: 実際のサイズは層数・KVヘッド数・精度によって変わり、このページは段の数だけを数えています。
博士

博士の一言：一度下ごしらえした食材は、二度下ごしらえしない。それがKVキャッシュです。

5上級

専門家混合（MoE）— 巨大な行列の代わりに小さな専門家たち

モデル: ルーターが128人から8人を選ぶ日常: 料理長が専門の料理人を配置する

名前の読み方 — Qwen3MoeForCausalLM

Qwenモデルファミリー（ブランド名）
3ファミリー内のアーキテクチャの主要バージョン
Moe専門家混合モデル
CausalLM因果言語モデル: 前のトークンだけを見て次を予測

本の解説のとおりです[1]。因果言語モデルは、両側の文脈で空欄を埋めるマスク言語モデルとは異なり、今日の生成LLMはすべて因果言語モデルです。同じアーキテクチャの中にも、複数のサイズ（例: Llama 8B・70B）、base・instruct の派生版、LoRA のようなファインチューニングがありますが、アーキテクチャは変わりません。

厨房では

料理人一人がすべての料理を作る代わりに、専門の料理人を128人置き、料理長（ルーター）が皿ごとに8人だけを呼び出します。お客が一人なら8人だけが忙しい。しかし夜の営業でお客が殺到すると、皿ごとに別の料理人を呼ぶことになり、結局ほぼ全員が忙しくなります。

限界: 実際のルーターは皿ごとに一度ではなく、94個の層ごとに選び直します。さらに、休んでいる専門家もメモリには載っている必要があります。

ニューラルネットワークでは

MoEは線形層に疎性を加えます。大きな行列一つの代わりに小さな行列（専門家）を数百個置き、入力ごとに数個だけを活性化します。Qwen3-235B-A22Bは、リクエストごとに2,350億のうち220億パラメータを、128の専門家のうち8個を、94個の層ごとに選びます。バッチ推論ではリクエストごとに異なる専門家が稼働するため、ほぼすべてのパラメータが稼働していると考える必要があります[1]。

実験 ⑤ — 一つの層、専門家128人、バッチサイズを変えて

1

動きで見る — 料理長がトークンを専門家に送る

解説 — 一人で使うときとサーバーで使うとき

  1. ニューラルネットワークの密度は、層の間の接続数で決まります。密なほど多くの情報を持ち、疎なほど計算とメモリが少なくて済みます[1]。
  2. リクエスト1つを単独で動かすと、稼働パラメータが少ないのでMoEは非常に効率的です（ローカルの単一リクエスト）。
  3. バッチを増やすと、トークンごとに選ばれる専門家が異なるため、稼働する専門家の和集合が急速に大きくなります。上の実験ではバッチ64でほとんどが稼働します。
  4. そのため大規模なサービスでは、複数のGPUに専門家を分けて載せるエキスパート並列化によって疎性を活かします。本の図2.9の例では、GPU 8台がそれぞれ16人の専門家を担当し、ルーターは各GPUに複製されます[1]。
  5. 32B未満、特に8B未満のモデルでは、従来の密な構造のほうが効率的な傾向があります。タブの自動補完のような限定分野のモデルは、モデル全体が実質的に専門家一人なので、MoEの利点は小さくなります[1]。

この段の限界: 稼働パラメータ数だけではサーバーのコストは数えられません。バッチ・並列化の方式・メモリを合わせて見る必要があります。その計算（演算対バイトの比率、ボトルネック）は本の2.4節と5.4.2節で続きます。

数式で見る

E人の専門家のうちトークンごとにK人を選び、ルーティングが均等に広がると仮定すると、バッチBで特定の専門家が一度も選ばれない確率は (1 − K/E)B、稼働する割合の期待値は 1 − (1 − K/E)B です。E = 128、K = 8、B = 64 のとき 1 − (15/16)64 ≈ 0.984。上の実験は人気の高い専門家がいる偏ったルーティング（シード 2026）を使うため、この値よりやや低く出ます。どちらも説明用のモデルです。

現場に置き換えると

「稼働 22B」という表示を見て、22B分のGPUメモリだけを用意してはいけません。専門家はすべてメモリに載っている必要があり、バッチを増やすと、ステップごとにほぼすべての専門家の重みを読み込むことになります。

たとえの限界: 実際のルーティングの分布はモデルとデータによって異なり、このページの偏りの程度は仮定です。

たとえがずれるところ

  • 配合表のたとえが似ているのは、行列の「掛けて足す」だけです。実際の行列は数千×数千の大きさで、値は学習によって決まります。
